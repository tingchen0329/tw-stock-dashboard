# 效能測試報告：v5.1 vs v6

測試日期：2026-10-20　｜　工具：`tests/bench/run_bench.py`、`tests/bench/search_bench.mjs`

## 方法

兩個版本在**同一個 headless Chromium 141** 中執行。所有對外請求都被攔截，
用**同一份合成資料**（上市 1,014 檔、上櫃 709 檔，與真實市場同級）與**同一組延遲假設**回應，
因此差異只來自程式架構。每項取 5 次的中位數。

| 網路延遲假設 | 數值 | 依據 |
|---|---|---|
| 公共 CORS proxy（corsproxy.io 等） | 1,200 ms | 免費 proxy 常見值，實際常 1–5 秒且會失敗 |
| FinMind API 直連 | 400 ms | |
| Stooq 直連 | 200 ms 後失敗 | Stooq 未開放 CORS，瀏覽器會擋 |
| cdnjs（SheetJS，約 880 KB） | 150 ms | |
| GitHub Pages 靜態檔 | 60 ms | CDN |

傳輸量以 gzip 後大小估算（GitHub Pages 與 proxy 都會壓縮）。

> 限制：這是模擬環境，絕對秒數會隨你的網路不同；但「請求次數」「是否依賴 proxy」「有無快取」
> 是程式結構決定的，不受網路影響。要重跑：`python tests/bench/run_bench.py --runs 5`

## 結果

| 指標 | v5.1 | v6 | 改善 |
|---|---|---|---|
| 開頁到可用 | 3.94 s | **0.48 s** | 8.2 倍 |
| 開頁下載量 | 309 KB（其中 SheetJS 約 293 KB，阻塞渲染） | **132 KB**（含全市場行情 + 2,052 檔股票清單） | −57% |
| 查詢追蹤清單股票：看到價格 | 7.98 s（全部完成才顯示） | **0.012 s** | 立即 |
| 查詢追蹤清單股票：全部完成 | 7.98 s，16 個請求 | **0.10 s，1 個請求** | 80 倍 |
| 再查同一檔 | 7.97 s，16 個請求（無快取） | **0.034 s，0 個請求** | 快取命中 |
| 查詢清單外股票 | 同上 | 價格 0.018 s；全部 0.89 s，8 個請求 | |
| **公共 proxy 全掛時：開頁** | **30.3 s** | **0.53 s** | 不受影響 |
| **公共 proxy 全掛時：查詢** | **60.7 s**，且缺本益比、法人 | **0.10 s** | 不受影響 |
| 一檔完整指標計算（786 交易日） | — | 3.0 ms | |
| 前端程式大小（gzip） | 13.6 KB + SheetJS 約 290 KB | 40.7 KB，零外部依賴 | |

「proxy 全掛」就是你之前截圖看到的「Proxy 全部失敗，稍後重試」情境。舊版每個透過 proxy 的請求要等
3 個 proxy × 10 秒逾時；新版完全不經過 proxy（伺服器端先抓好），所以不受影響。

- **單次搜尋 v6 比較慢**（約 10 倍），因為要搜 16 倍的股票並做排序與模糊比對。
  但最慢 0.17 ms，遠低於一個畫面更新的 16 ms，使用上感覺不到。
- **涵蓋率**：隨機抽 200 檔用名稱搜尋，第一筆就正確 —— v5.1：**3 / 200**，v6：**200 / 200**。
  v5.1 的清單是手打的 129 筆（其中 2 筆重複）。

## 為什麼變快

1. **不再經過公共 CORS proxy**：證交所 / 櫃買 / Yahoo 改在 GitHub Actions 伺服器端抓取（沒有 CORS 限制）。
2. **全市場資料一次載入、整頁共用**：舊版每次查詢都重新下載證交所三份全市場檔案。
3. **先畫再補**：點選後先用已載入的全市場行情畫出價格與估值，詳細資料回來再補上。
4. **快取與請求共用**：同一網址一個分頁只抓一次；同時要同一份資料只發一個請求。
5. **SheetJS 改為自製 .xlsx 寫入器**（約 120 行），不再阻塞首頁渲染。
6. **modulepreload**：所有 JS 模組平行下載，不必等 main.js 解析後才發現依賴。
